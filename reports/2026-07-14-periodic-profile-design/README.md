# 周期性任务三剖面前端设计稿

日期：2026-07-14
范围：设计并实现前端页面与交互；月、年剖面组合现已纳入 clean Project 持久化边界。

## 1. 设计目标

将“周期性任务建模”从单一的周列表编辑器调整为三个互相联动的列表剖面：

- **周剖面列表**：维护多个可命名的周模板；每个周剖面内配置周一至周日的复合任务。
- **月剖面列表**：维护多个可命名的月模板；每个月剖面按第 1—4 周的固定坑位映射周剖面，必要时增加第 5 周。
- **年剖面列表**：维护多个可命名的年度规划；每个年剖面组织 12 个月和月剖面引用。

三种剖面是同一周期性任务的三级列表，不应各自维护一份互相漂移的数据。现有按周配置继续作为运行时展开的基础；月、年配置在保存或运行前展开为周级计划。

## 3. 三个剖面的页面结构

### 3.1 周剖面列表

保留当前页面的细粒度编辑能力，但将左侧从“第 N 周”改为可命名的周剖面列表。

- 左侧只显示当前标签对应的周剖面列表，支持新增、删除和重命名；不显示总任务名称。
- 中间：固定周一至周日七行；每行选择复合任务或“无任务”。
- 工具栏：复制周剖面、清空当前剖面、查看引用该剖面的月/年剖面。
- 右侧检查器：编辑剖面名称，显示当前剖面被哪些月剖面引用。
- “无任务”和“未配置”必须视觉区分：前者是明确业务选择，后者是缺失配置。

### 3.2 月剖面列表

月视图展示可命名的月剖面列表；一个月剖面由按周次固定排列的周剖面坑位组成。

- 左侧只显示月剖面列表，支持新增、删除和重命名。
- 中间：第 1—4 周为固定坑位，每个坑位单独选择一个周剖面；同一周剖面可在多个周次中选用。
- 一个抽象规划月默认配置 4 个坑位，最多增加第 5 周；不使用“重复周数”或排序控制表达连续周。
- 第 5 周是显式的可选坑位，可单独添加或移除；前 4 周始终保留，避免月配置少于 4 周。
- 这里表达的是任务规划周期，不按自然月日历格对齐；若后续需要按日期处理跨月的不完整周，应另行定义起始日期和拆周规则。
- 覆盖已有周配置时先弹出预览确认，明确“将修改多少周”。

### 3.3 年剖面列表

年视图用于规划和批量操作，不承担周内任务的逐行编辑；年度本身是可命名列表项。

- 左侧只显示年剖面列表，支持新增、删除和重命名。
- 中间：固定 12 个月网格，每个月分别选择一个月剖面。
- 12 个月引用的月剖面合计应为 52 周；常见组合是 8 个 4 周月和 4 个 5 周月。
- 工具栏：复制年剖面、年度差异对比、查看引用链。
- 右侧检查器：编辑年剖面名称，显示年度汇总（规划周数、已配置周数、无任务周数、冲突数）。
- 点击月份进入月剖面列表中的对应项；点击月份中的周摘要进入周剖面列表中的对应项。

#### 三年任务配置

- 年剖面列表的顺序就是多年任务的年度顺序：第 1 项为第 1 年，第 2 项为第 2 年，以此类推。
- 配置三年任务时，年剖面列表应有三个列表项；每项分别维护 1—12 月的月剖面引用。
- 可将当前年复制为下一年，再修改少量月份；复制后各年度相互独立。
- 年剖面可重命名，但序号“第 1 年 / 第 2 年 / 第 3 年”由列表位置决定，不随名称变化。

## 4. 关键交互

1. **剖面切换**：只切换视图，不改变任务数据；切换前若有未保存修改，提示保存或放弃。
2. **列表项重命名**：三种列表的每个项均可行内重命名；名称不能为空，重复名称需提示；回车保存，Esc 取消。
3. **月模板下发**：选择月剖面后，先展示“影响的周剖面列表 + 覆盖数量”，确认后再写入周级草稿。
4. **年度复制**：默认复制为独立年剖面；复制完成后目标年剖面可单独修改，不建立隐式联动。
5. **范围选择**：编辑某周剖面时可选“当前周剖面 / 当前任务段 / 同模板全部周剖面”。
6. **任务段冲突**：出现重叠时禁止静默覆盖，提供“拆分 / 替换 / 取消”三选项，并标出受影响的月剖面和周剖面。
7. **完整性检查**：检查任务名称、各级剖面名称、规划年数、月/周剖面引用、未配置项、冲突段和失效复合任务引用；结果可定位到对应列表项。
8. **保存反馈**：顶部状态依次为“未保存修改 → 保存中 → 已保存”或“保存失败”；失败时保留草稿，不清空编辑内容。

## 6. 状态与空态

| 状态 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 无周期任务 | 三个剖面列表均显示空态，引导“新增周期性任务” | 新增 |
| 列表为空 | 当前剖面列表显示“暂无剖面”，提供新增和从其他列表复制 | 新增/复制 |
| 名称重复 | 行内重命名时显示重复提示，不允许保存 | 修改名称 |
| 未配置 | 灰色状态点，提示需要配置 | 进入编辑 |
| 无任务 | 明确的“无任务”标签，不计入缺失配置 | 修改/清除 |
| 部分配置 | 黄色状态点，显示已配置周数/总周数 | 定位缺失周 |
| 有冲突 | 红色提示，列出重叠段 | 拆分/替换 |
| 旧数据 | 显示“已兼容旧周计划”，只在首次保存时生成新视图索引 | 查看/保存 |
| 无复合任务 | 禁用任务下拉框并提示先维护复合任务 | 跳转复合任务建模 |

## 7. 验收标准（设计阶段）

- 年剖面不出现 52/156 行周级编辑表，只显示年度—月份—任务段摘要。
- 周、月、年三类剖面均以列表呈现，列表项均可重命名、复制、删除和排序。
- 月剖面能够明确展示月份到周的映射，并可一键定位到周剖面。
- 月剖面以第 1—4 周固定坑位配置不同周剖面，必要时增加第 5 周；达到 5 周后不能继续添加。
- 每个年剖面的 12 个月引用合计为 52 周，并能明确提示不足或超出。
- 周剖面仍能完成当前的周一至周日复合任务配置和复制操作。
- “无任务”与“未配置”可区分，完整性检查不会把明确无任务误报为缺失。
- 月/年批量操作均有影响范围预览和覆盖确认。
- 旧的 `periodicTasks[]` 数据读取后不丢失，刷新页面后视图状态一致。
- 本阶段不改变仿真展开契约；运行时仍消费展开后的周级任务计划。

## 8. 交接给前端实现

实现顺序建议：

1. 抽出 `periodicEditor` 视图状态和三类剖面列表，不改变数据结构。
2. 先完成三类列表的新增、重命名、复制、删除、排序和状态标识。
3. 先完成周剖面列表的细粒度编辑，保证现有功能回归。
4. 增加月剖面列表、周映射和模板预览。
5. 增加年剖面列表、年度复制和差异摘要。
6. 最后接入任务段范围编辑、冲突处理和完整性检查。

本设计暂不需要新增图片资源；使用现有图标、状态徽标、日历/时间轴的 CSS 组件即可。

## 9. 空配置与持久化补充（issue #250）

- 月剖面的第 1—4 周和可选第 5 周、年剖面的 1—12 月均以空字符串 `""` 表示“未配置”；新建剖面默认全部为空，不自动引用首个可用剖面。
- 下拉框的“未配置周剖面 / 未配置月剖面”是可保存的显式空选项。删除被引用的周或月剖面时，对应引用也清空，不改指向列表中的其他首项。
- `missionProfile.periodicProfileLists` 已进入 `aircraft_support_v1_project.schema.json` 和后端 Project 清洗白名单，保存、重新读取与前端回显保持空值和非空引用不变。
- 月汇总显示“已配置周数 / 周坑位数”及“完整 / 待配置”；年汇总显示“已配置月数 / 12 月”、有效周数 / 52 周及“有效 / 待完善”。空槽不计为有效周，也不参与仿真展开。
- 当前仿真仍由 `missionProfile.periodicTasks[]` 的周级任务计划驱动；`periodicProfileLists` 是持久化的规划组合和回显数据。编译器稳定忽略空槽，不把它们补成首项。
