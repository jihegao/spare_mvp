| --- | --- |
| 文档版本 | V0.1 |

## 1. 背景与目标

当前前端原型已经补齐两个建模入口：

1. 备件规划评估模块 / 备件规划仿真建模。
2. 任务可靠度评估模块 / 任务可靠度仿真建模。

这两个页面目前只提供静态评审表达，用于说明建模范围和页面入口。下一阶段需要把它们细化为可开发、可验收、可接后端和可支撑 `core/` 数据适配的建模需求。

本需求目标：

1. 固定两个建模页面的最小对象、字段、规则和验收口径。
2. 明确两页共享字段和差异字段。
3. 为后续项目数据契约、实验方案契约、后端 API、运行产物和 `core/` 适配提供输入。
4. 避免后续直接从静态演示字段反推后端数据模型。

## 2. 需求边界

### 2.1 本阶段覆盖

| 范围 | 说明 |
| --- | --- |
| 页面信息架构 | 明确两页需要展示和维护的对象分组 |
| 最小字段 | 固定 MVP 最小字段，不覆盖远期完整建模编辑器 |
| 校验规则 | 明确必填、数值范围、引用关系和重复编号校验 |
| 导入导出 | 支持最小项目 JSON 导入导出需求 |
| 实验联动 | 建模数据应能被对应仿真实验方案引用 |
| 后端契约输入 | 为后续 API 和产物 JSON 定义提供字段来源 |

### 2.2 本阶段不覆盖

| 不覆盖项 | 说明 |
| --- | --- |
| 完整图形化建模编辑器 | MVP 阶段可用表单、表格和简单层级视图替代 |
| 完整权限体系 | 仅保留项目级数据归属字段 |
| 长周期大样本调度 | 归入系统运行支持和实验运行阶段 |
| 高精度优化算法 | 先固定输入字段，算法精度在后端闭环阶段确认 |
| 复杂数据库设计 | 可先使用文件型项目 JSON 和运行产物目录 |

## 3. 两页共用建模能力

### 3.1 共用对象分组

| 对象分组 | 最小用途 | 后续消费者 |
| --- | --- | --- |
| 项目场景 | 固定示例项目、场景名称、任务周期和作战单元 | 实验方案、运行产物 |
| 任务建模 | 描述任务、波次、阶段、持续时间和任务目标 | 仿真实验、任务完成度评估 |
| 装备建模 | 描述装备、数量、组成、部件或 LRU | 故障模型、备件关联、可靠性框图 |
| 保障组织 | 描述保障站点、保障人员、保障设备和保障能力 | 维修活动、保障资源约束 |
| 保障活动 | 描述修复性维修、预防性维修、使用保障和资源需求组 | 仿真运行、停机因素分析 |
| 指标方案 | 描述可用度、满足率、可靠度、失效率、MTBF 等目标 | 实验方案、结果分析、验收指标 |

### 3.2 共用页面行为

| 行为 | 需求 |
| --- | --- |
| 查看 | 用户可以查看当前项目的所有建模对象分组 |
| 编辑 | MVP 至少支持表格或表单方式编辑关键字段 |
| 新增 | MVP 至少支持新增任务、装备、备件或部件、保障资源记录 |
| 删除 | MVP 至少支持删除未被其他对象引用的记录 |
| 保存 | 保存后生成项目数据版本或更新时间 |
| 校验 | 保存前执行字段必填、数值范围和引用关系校验 |
| 导出 | 用户可以导出最小项目 JSON |
| 导入 | 用户可以导入符合契约的项目 JSON，并显示校验结果 |
| 实验引用 | 已保存建模数据可被同模块仿真实验方案选择 |

### 3.3 共用状态

| 状态 | 说明 |
| --- | --- |
| 草稿 | 用户正在编辑，尚未通过校验或保存 |
| 已保存 | 建模数据已通过基础校验并可被实验方案引用 |
| 有错误 | 存在必填、范围或引用关系错误 |
| 只读示例 | 当前静态原型或演示项目数据，不承诺真实后端保存 |

### 3.4 共用校验规则

| 规则 | 说明 |
| --- | --- |
| 编号必填 | 任务、装备、部件、备件、保障资源、活动和指标方案必须有唯一编号 |
| 名称必填 | 用户可见对象必须有名称 |
| 非负数 | 数量、库存、周期、时长、样本数、人员数和设备数不能为负 |
| 概率范围 | 满足率、可靠度、可用度等比例字段范围为 0 到 1，或以前端显示映射为 0% 到 100% |
| 引用存在 | 备件引用部件、活动引用资源、故障模型引用装备时，被引用对象必须存在 |
| 删除保护 | 被实验方案或其他对象引用的记录不能直接删除 |
| 单位明确 | 时间、数量、概率、频次等字段必须有单位或口径说明 |

## 4. 备件规划仿真建模需求

### 4.1 页面定位

备件规划仿真建模用于维护备件规划实验所需的任务、装备、保障组织、备件、保障活动和指标方案数据。其输出应支撑：

1. 备件规划仿真实验。
2. 备件短板分析。
3. 转场携行清单分析。
4. 后端备件需求、库存消耗、补给延误和携行建议的最小计算或启发式映射。

### 4.2 对象与字段

#### 4.2.1 项目场景

| 字段 | 类型 | 必填 | 说明 |

| `baseUnit` | string | 否 | 基本作战单元描述 |
| `dataVersion` | string | 否 | 项目数据版本 |

#### 4.2.2 任务建模

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

#### 4.2.3 装备建模

#### 4.2.4 备件建模

#### 4.2.5 保障组织与资源

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `orgId` | string | 是 | 保障组织编号 |
| `orgName` | string | 是 | 保障组织名称 |
| `siteType` | enum | 否 | 基地 / 转场 / 前沿 / 其他 |

| `carryReliabilityThreshold` | number | 否 | 携行清单任务可靠度阈值 |

### 4.3 业务规则

1. 一个备件必须关联至少一个装备部件或 LRU。
2. 初始库存、基层级库存、保障人员数、保障设备数和装备数量必须为非负整数。
3. 任务波次数和每波出动架次必须大于 0。
4. 保障活动引用的装备、备件和资源必须已存在。
5. 转场携行清单可继续沿用“优化条件 + 任务可靠度 + 备件满足率 + 备件利用率”的页面交互，但携行数量应由后端最小规则或启发式规则输出。
6. 备件短板分析至少需要从建模数据和运行结果中得到备件满足率、平均延误时间、基层级数量、初始基层级库存、不满足次数和短板等级。

### 4.4 验收标准

| --- | --- | --- |
| SP-M-01 | 页面入口 | 可从首页进入 `#/spare-planning/modeling`，标题为“备件规划仿真建模” |
| SP-M-02 | 对象完整性 | 页面展示任务、装备、备件、保障组织、保障活动和指标方案分组 |
| SP-M-03 | 关键字段 | 至少可维护任务编号、装备编号、备件编号、库存、补给提前期和保障资源数量 |
| SP-M-04 | 引用关系 | 备件可关联装备部件，保障活动可关联装备和资源 |
| SP-M-05 | 校验 | 负库存、空编号、重复编号和不存在引用应提示错误 |

| SP-M-08 | 结果联动 | 字段口径可支撑备件短板分析和转场携行清单分析 |

## 5. 任务可靠度仿真建模需求

### 5.1 页面定位

任务可靠度仿真建模用于维护任务可靠度实验所需的任务剖面、装备故障、可靠性框图、保障组织、保障活动和指标方案数据。其输出应支撑：

1. 任务可靠度仿真实验。
2. 任务完成度评估。
3. 停机因素分析。
4. 后端任务成功概率、装备可用状态、停机归因和可靠度统计的最小计算或规则映射。

### 5.2 对象与字段

#### 5.2.1 任务剖面

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `profileId` | string | 是 | 任务剖面编号 |
| `profileName` | string | 是 | 任务剖面名称 |
| `wave` | integer | 是 | 波次序号 |
| `phaseName` | string | 是 | 任务阶段名称 |
| `durationHours` | number | 是 | 阶段持续时间 |
| `requiredAircraft` | integer | 是 | 当前阶段所需可用飞机数 |
| `successCriteria` | string | 是 | 成功判定条件 |

#### 5.2.2 装备与部件

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

| `aircraftType` | string | 是 | 装备型号 |
| `quantity` | integer | 是 | 装备数量 |
| `lruId` | string | 是 | LRU 或部件编号 |
| `lruName` | string | 是 | LRU 或部件名称 |
| `parentId` | string | 否 | 上级系统或部件编号 |

#### 5.2.3 故障模型

| 字段 | 类型 | 必填 | 说明 |

#### 5.2.5 保障组织与活动

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `orgId` | string | 是 | 保障组织编号 |

| `targetMttrHours` | number | 否 | MTTR 目标 |
| `importedRmsResultPath` | string | 否 | 整机到 LRU 级 RMS 结果导入路径 |

### 5.3 业务规则

1. 任务剖面必须至少包含一个波次和一个任务阶段。
2. 装备故障模型必须引用已存在的 LRU 或部件。
3. 可靠性框图必须至少支持系统到 LRU 两级结构。
4. 串联、并联和 k-out-of-n 关系在 MVP 阶段可先以结构化表格表示，不要求图形拖拽编辑。
5. 故障率、可靠度和成功概率必须满足有效数值范围。
6. 停机因素分析至少需要从运行结果或规则映射中归集“无可用飞机”“飞机故障”和二级因素贡献。
7. 任务完成度评估至少需要输出波次任务成功概率、累计出动架次、可用飞机数和状态。

| MR-M-03 | 故障参数 | 至少可维护故障率、MTBF、MTTR 和维修时间 |

| MR-M-05 | 指标分配 | 支持系统可靠度、任务可靠度、失效率、MTBF 和 MTTR 目标字段 |

## 6. 两页差异化边界

| 维度 | 备件规划仿真建模 | 任务可靠度仿真建模 |
| --- | --- | --- |
| 主要目标 | 支撑备件需求、库存、补给和携行建议 | 支撑任务成功概率、装备可用性和停机归因 |
| 重点对象 | 备件、库存、补给提前期、保障资源 | 故障模型、可靠性框图、任务剖面、RMS 指标 |

| 后续实验 | 备件规划仿真实验 | 任务可靠度仿真实验 |
| 最小算法依赖 | 备件消耗、库存扣减、补给延误、携行启发式 | 故障抽样、维修时间、可用飞机数、波次成功判定 |

## 8. 后续任务拆分建议

| 顺序 | 工作包 | 说明 |
| --- | --- | --- |
| 1 | 路线 A 建模页验收 | 确认两个静态建模页入口、范围说明和边界提示通过 |
| 2 | 建模字段契约 | 将本文字段转为正式 JSON schema 或字段表 |
| 3 | 前端表单细化 | 把只读静态配置区升级为表单、表格和校验提示 |
| 4 | 后端项目数据 API | 提供项目建模数据读写、导入和导出能力 |
| 5 | `core/` 数据适配 | 将项目 JSON 映射为仿真内核或聚合层输入 |
| 6 | 实验联动 | 让仿真实验方案引用已保存建模数据并生成运行产物 |

## 9. 开放问题

1. MVP 第一版是否用文件型项目 JSON 作为唯一持久化方式，还是引入轻量数据库。
2. 备件规划和任务可靠度是否共享同一套任务、装备、保障组织基础对象，还是分模块独立保存。
3. 可靠性框图在 MVP 阶段是否需要图形化展示，还是表格层级结构即可。
4. 故障率、MTBF、MTTR 等可靠性字段是否以概要设计文档为准，还是以 `core/dataset/` 当前数据为准。
5. 备件携行建议在 MVP 阶段采用启发式规则、简化优化，还是接入现有 `core/` 候选能力。
6. 指标方案导入是否需要支持文件上传，还是先使用固定示例路径和 JSON 字段。
