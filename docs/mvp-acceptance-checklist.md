## 1. 验收边界

本清单用于验收当前项目的全功能最小闭环 MVP，不再只检查静态页面。MVP 必须证明以下链路成立：

```text
建模输入 -> 实验方案 -> 后端计算或本地服务 -> 结果持久化 -> 前端展示 -> 验收产物
```

Phase 0 静态前端基线仍然有效，但它只是页面、路由、字段表达和评审沟通基线，不代表后端、仿真或真实运行闭环已经完成。

验收时必须区分四类结果来源：

| 来源类型 | 是否可作为 MVP 真实结果 | 使用边界 |
| --- | --- | --- |
| Phase 0 静态常量 | 否 | 只能作为页面基线、空状态、演示状态或无服务降级夹具 |
| 最小规则或启发式映射 | 可以，但必须标注 | 可用于转场携行清单等 MVP 简化能力 |
| `core/` 仿真输出 | 可以，但必须经字段契约和测试确认 | 不得未经测试直接声称为产品算法输出 |
| 后端聚合结果 JSON | 是 | MVP 结果分析页面的优先数据来源 |

```bash
awk 'BEGIN{bad=0} /^\\|/ { n=gsub(/\\|/,"&"); if (lastfile==FILENAME && prevbar>0 && n!=prevbar && prevline ~ /^\\|/) { print "table column change near " FILENAME ":" FNR " prev=" prevbar " now=" n; bad=1 } prevbar=n; prevline=$0; lastfile=FILENAME; next } { prevbar=0; prevline=$0; lastfile=FILENAME } END{exit bad}' docs/*.md
```
