# 基本保障活动统一 CSV 导入契约

## 页面与落地边界

“基本保障活动建模”页面只提供一个本地 CSV 文件入口。活动类型来自每一行的“活动类型”字段，同一文件可以混合使用保障活动、预防性维修和修复性维修；页面不再按当前筛选类型生成伪导入记录。新增、编辑、批量删除、类型筛选和文本查询继续使用原有入口。

CSV 只是一种 Project draft 数据录入适配器，不新增后端资源或 Project 根字段。导入成功后，基本保障活动定义写入浏览器草稿的顶层 `supportActivityJobs[]`；对应 `supportActivities[]` 目标宿主只持有 `activityCodes[]` 和 `predecessors`。页面刷新为全部类型视图并显示导入数量，然后沿既有 Project draft 标脏、自动保存和显式保存边界持久化。导入失败不修改 Scenario、不增加 draft revision，也不调度自动保存。

## v1 模板列

下载模板使用 UTF-8 BOM 和以下固定列顺序：

| 列 | 必填规则 | 说明 |
| --- | --- | --- |
| 活动类型 | 必填 | `使用保障活动`、`预防性维修`、`修复性维修` |
| 基本保障活动编号 | 必填 | `supportActivityJobs[].activityCode` 全局主键，1–64 位字母、数字、点、下划线或连字符 |
| 基本保障活动名称 | 必填 | 最长 120 个字符 |
| 适用飞机 | 可空 | 非空时必须精确引用当前 Project 的整机型号 |
| 作业时长分布 | 必填 | `固定值`、`指数分布`、`正态分布`、`均匀分布` |
| 固定工期(min) | 条件必填 | 固定值使用，必须大于 0 |
| 均值(min) | 条件必填 | 指数或正态分布使用，必须大于 0 |
| 标准差(min) | 条件必填 | 正态分布使用，必须大于 0 |
| 最小值(min) | 条件必填 | 均匀分布使用，必须大于 0 |
| 最大值(min) | 条件必填 | 均匀分布使用，必须大于等于最小值 |
| 紧前作业 | 可空 | 多个编号用 `;`、`；`、`、` 或 `|` 分隔 |

v1 CSV 只批量录入基础标识、适用飞机、工期分布和 DAG 引用。人员、设备和备件需求继续在导入后使用现有编辑面板按 Project 资源唯一标识配置；导入不会生成虚构资源，也不会改变既有新增、编辑、批量删除和查询功能。#307 的 CSV 不增加“维修方式”或“换件比例”列：`maintenanceMethods` / `replacementRatio` 属于修复性或预防性 `supportActivities[]` 宿主方案，不属于可复用的 `supportActivityJobs[]` 作业定义。

导入器按 RFC 风格处理逗号、双引号、CRLF 和引号内换行，未加引号字段中的裸双引号作为语法错误拒绝，并把错误定位到数据记录的物理起始行。单文件上限为 1 MiB （按 UTF-8 真实字节数）和 1000 条数据；文件入口会先检查 `file.size` 再读取文本。所有单元格都只按文本处理；以 `=`、`+`、`-` 或 `@` 开头的内容拒绝导入，避免后续进入电子表格时形成公式注入。聚合错误的用户可见文案最多展示 20 项且每项最多 240 个字符，超出部分显示剩余数量，但不改变整批失败的原子性。

## 校验与原子性

解析器先在 detached 数据中完成全部校验，再由页面对克隆 Scenario 做 staging。只有 staging 全部成功，才一次替换当前草稿并标脏一次。任一错误都会聚合为“第 N 行 [字段] 原因”，整批零落地。

校验至少包括：

- 文件扩展名、空文件、CSV 语法、空/重复/未知表头和必填表头；
- 活动类型、全局唯一活动编号、名称、适用飞机、时长分布和对应数值参数；
- 紧前作业只允许引用同一类型、同一目标宿主中的既有唯一 `activityCode`，或本批同类型编号；
- 未知、跨类型、跨宿主、歧义、自引用、重复引用和循环引用全部失败关闭；
- 批内编号或与当前 Project 顶层 `supportActivityJobs[]` 重复时直接拒绝，不静默改码。

## 兼容策略

规范写出只使用上表中文列名。读取时兼容以下旧称或自动化别名：

- `保障类型`、`activityType`、`type`；
- `活动编号`、`activityCode`、`code`；
- `工作项目名称`、`workName`、`name`；
- `适用对象`、`适用机型`、`applicableAircraft`、`aircraftModel`；
- `工期分布`、`distributionType` 及各时长参数的既有中英文别名；
- `紧前作业编号`、`predecessors`。

类型值 `使用保障` 规范化为 `使用保障活动`，`预防性维修活动` 和 `修复性维修活动` 分别规范化为无“活动”后缀的 canonical 值。旧页面的“按活动类型导入”只是本地生成默认行，没有真实文件格式，因此不保留该伪入口，也不把其他页面的工作项目 CSV 当作本模板自动猜测。
