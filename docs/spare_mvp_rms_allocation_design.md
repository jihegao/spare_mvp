# RMS 指标分配方法与当前实现

## 当前边界

装备 RMS 指标分配是系统运行支持模块下的本地份额分配工作台。飞机型号来源于当前 Project 的装备系统建模；选择机型后，页面只投影该机型的装备结构。安装数和运行比仍是 RMS 工作台编辑值，不回写装备系统建模中的 MTBF/MTTR 字段。

当前页面不再提供反算模块。计划与结果保留任务时长、MTBF、MTTR 输入及其快照，但页面和 XLSX 导出不展示目标 R、任务可靠度输入、校核可靠度、MTBCF 或 MTTR 裕度。工作台只保留计算和导出，不提供独立的保存或发布按钮；机型选择、三项 RMS 输入、树选中状态、工作台装备值和结果会按机型写入 Project draft 的 RMS 过程字段，并在正式 Scenario 编译前剥离。

## 页面结构

页面按以下 DOM 与视觉顺序组织：

1. “机型选择与数据准备”区块，包括飞机型号、下载模板和上传文件；未选择机型时上传入口禁用，下载模板仍可使用。下载模板与上传文件按钮尺寸一致。
2. 当前机型的左侧“装备结构树”只展示结构树，右侧表格展示当前选中节点及其子节点的系统名称、型号、安装数和运行比，两侧不混放数据准备或计算按钮。
3. “RMS 输入与指标分配计算”区块在同一面板内按“RMS 输入参数 -> 指标分配方法 -> 执行计算”组织任务时长、MTBF、MTTR、方法参数、计算按钮、校验信息和计算状态；任务可靠度与关键故障占比不再作为页面输入。
4. “节点分配结果”区块及真实 XLSX 导出。

导入模板字段为节点 ID、父节点 ID、系统名称、型号、层级、安装数和运行比。导入数据只更新 RMS 工作台内存状态。

子系统安装数必须是正整数；运行比必须是 `0..1` 的有限数。缺失或非法值会拒绝整次导入，不做默认值补齐、四舍五入或截断。运行比可以为 0，但比例法或相似产品法的全部节点权重为 0 时计算失败，不产生“已分配”结果。

## 分配契约

`rms-allocation-plan-v5` 声明任务时长、整机 MTBF、整机 MTTR 三项 RMS 数值输入、分配方法及其参数。计算前必须选择飞机型号，并校验任务时长 `> 0 h`、MTBF `> 0 h`、MTTR `>= 0 h`。`rms-engine-5.0.0` 的结果同时记录当前飞机型号和三项输入快照；旧 plan 中的 `missionReliability` 只允许迁移读取，规范化后会被丢弃，不参与计算或后续保存。每个节点结果固定包含：

- 层级、节点、型号；
- 安装数、运行比；
- 节点失效率、MTBF、MTTR；
- 分配份额、状态。

三种规则先生成原始权重：等分配法对参与节点取 `1`；比例分配法取 `安装数 × 运行比 × 重要度 × 复杂度`；相似产品分配法取基准机型对应节点的 `安装数 × 运行比`。归一化后的权重 `w_i` 合计为 1。运行比为 0 的目标节点权重固定为 0，不生成伪造指标；若全部权重为 0 则计算失败关闭。

整机风险预算为 `T / MTBF_equipment`，节点风险预算为 `w_i × T / MTBF_equipment`。节点产品强度为 `T × r_i`，因此 `MTBF_i = T × r_i / risk_i`，`failureRate_i = 1 / MTBF_i`，并满足 `Σ(r_i × failureRate_i) = 1 / MTBF_equipment`。MTTR 按节点维修难度 `d_i` 缩放，使失效率加权均值满足 `Σ(failureRate_i × MTTR_i) / Σ(failureRate_i) = MTTR_equipment`。相似产品基准必须存在、不能是当前装备，并且必须能为每个目标节点找到同名对应节点。旧版复制整机 MTBF/MTTR 的缓存会按当前算法版本重新计算。

## Excel 导出

前端把页面正在展示的节点结果原样提交到 `/api/rms-allocation/export-xlsx`。后端用 `openpyxl` 生成真实工作簿，结果表头顺序与页面一致：层级、节点、运行比、失效率、MTBF(h)、MTTR(h)。
