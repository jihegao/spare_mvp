# RMS 指标分配方法与当前实现

## 当前边界

装备 RMS 指标分配是系统运行支持模块下的任务可靠度分解工作台。页面先选择飞机型号，再从当前 Project 的 `basicMissions[]` 中选择适用于该机型的基本任务。任务时长只取所选基本任务的 `taskDurationMinutes` 并换算为小时，只读展示；`missionProfile`、复合任务、周期任务以及其他大周期任务剖面不作为 RMS 分配输入。

整机可靠性输入为所选基本任务时长 `T` 下的整机任务可靠度 `R(T)`。节点运行比由用户在装备组成树上配置，引擎内部使用 `T × 运行比` 计算节点任务使用时间，但页面、导入模板和保存结果均不增加“节点暴露”“暴露时间”或“暴露矩阵”字段。安装数、运行比和分解结果属于 RMS 工作台过程数据，不回写装备系统建模中的产品 MTBF/MTTR。

工作台支持装备组成/安装数导入，以及分解结果 XLSX 的导入、编辑、显式保存和再次打开恢复。RMS 计划和结果可以随 Project 草稿保存用于页面恢复，但在正式 Scenario 编译前仍会被剥离，不成为 Mesa 模型输入。

## 页面结构

页面按以下顺序组织：

1. “机型选择与数据准备”：选择飞机型号，下载或上传装备组成/安装数数据。
2. “装备结构树”：左侧递归展示整机、系统、分系统和 LRU，右侧编辑当前节点及其子树的系统名称、型号、安装数和运行比。
3. “RMS 输入与指标分配计算”：选择基本任务，只读查看任务时长，输入整机任务可靠度 `R(T)` 和整机 MTTR，再选择等分配、比例分配或相似产品分配并显式计算。
4. “节点分配结果”：递归展示系统、分系统和 LRU 的本层份额、失效率、MTBF、MTTR 及校核状态，并提供结果导入、编辑、显式保存和 Excel 导出。

装备组成导入字段为节点 ID、父节点 ID、系统名称、型号、层级、安装数和运行比。子节点安装数必须是正整数，运行比必须是 `0..1` 的有限数；缺失或非法值会拒绝整次导入，不做默认值补齐、四舍五入或截断。

结果导入以导出工作簿中的项目、机型、基本任务、计划和算法元数据校核当前上下文。重复或未知节点、上下文不匹配、非法数值和不完整结果均失败关闭，不部分覆盖当前结果。编辑结果后必须点击“保存分解结果”；保存成功后才更新可恢复快照，保存失败保留当前编辑并显示错误。

## 分配契约

当前 RMS 计划记录所选基本任务标识、整机任务可靠度 `R(T)`、整机 MTTR、分配方法和算法版本。任务名称和由基本任务派生的任务时长只进入结果输入快照，不作为可编辑的计划输入。计算前必须满足：

- 所选基本任务来自 `scenario.basicMissions[]`，适用于当前机型且任务时长大于 0；
- `0 < R(T) < 1`；
- 整机 MTTR 大于等于 0；
- 装备树无循环或悬空父节点，参与节点安装数和运行比合法。

整机风险预算为：

```text
H_equipment = -ln(R(T))
```

引擎从整机开始逐层分解。对同一父节点的直接子节点，三种规则先生成原始权重：等分配法对参与节点取 `1`；比例分配法取 `安装数 × 运行比 × 重要度 × 复杂度`；相似产品分配法取基准机型对应节点的 `安装数 × 运行比`。本层份额归一化后合计为 1，节点累计风险预算为父节点风险预算乘以本层份额。具有子节点的系统继续使用相同规则向下分解，直至 LRU 或叶节点。

节点任务使用时间和指标换算为：

```text
T_i = T × runningRatio_i
H_i = H_parent × localAllocationShare_i
MTBF_i = cumulativeInstallationCount_i × T_i / H_i
failureRate_i = 1 / MTBF_i
```

这里的 `T_i` 仅是公式内部量，不作为页面字段保存；累计安装数是装备树路径上各级安装数的乘积，因此结果中的 MTBF 是单件节点指标。运行比为 0 的节点不消耗本层风险预算，不生成伪造指标；某一分解层全部权重为 0 时计算失败。每层子节点风险预算之和必须等于父节点风险预算，根节点校核值必须回到输入的 `R(T)`。

MTTR 从整机开始逐层分配。对同一父节点的参与子节点，先计算故障贡献份额和维修停机时间预算份额：

```text
p_i = installationCount_i × failureRate_i
      / Σ(installationCount_j × failureRate_j)
s_i = repairDifficulty_i / Σ(repairDifficulty_j)
MTTR_i = MTTR_parent × s_i / p_i
```

因此每层都满足 `Σ(p_i × MTTR_i) = MTTR_parent`。维修难度缺失时取 `1`；当同层节点维修难度都为 `1` 时，停机时间预算等分，安装数和失效率形成的故障贡献差异仍会产生不同的组件 MTTR。改变安装数并重新计算时，比例分配法会同时更新可靠性份额、故障贡献和 MTTR。运行比为 0 的节点不参与 MTTR 分配，结果保持为空。

改变机型、基本任务、`R(T)`、整机 MTTR、分配方法、装备组成、安装数或运行比后，已有结果立即失效，必须重新计算或导入与当前上下文匹配的结果。递归结果按节点 ID 和父节点 ID 校核，不能把其他机型或其他基本任务的结果静默复用。

## 结果导入、编辑、保存与导出

“导出 Excel”生成包含当前上下文元数据和递归节点结果的真实 OOXML 工作簿；“导入分解结果”读取同一格式并先预览校核，再替换当前结果。结果表至少保留节点 ID、父节点 ID、层级、节点、运行比、本层份额、失效率、MTBF、MTTR 和状态，以支持无歧义的递归恢复。

MTBF 和 MTTR 可在结果表中编辑。编辑不会静默重跑算法；保存时记录当前飞机型号、基本任务、输入快照、装备树快照、算法版本和节点结果。只有当前上下文匹配且通过校核的结果才允许保存或导出。
