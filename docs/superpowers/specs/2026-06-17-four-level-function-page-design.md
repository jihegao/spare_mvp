# 四级功能页面化前端设计规格

日期：2026-06-17

## 背景

当前前端已经覆盖备件规划、任务可靠度、仿真实验和结果分析的核心概念，但页面组织仍偏向 6 个大视图：建模中心、可靠性框图、保障甘特、可视化仿真、蒙特卡洛、结果分析。这个结构适合原型演示，不适合承载 `docs/3概要设计方案.md` 中明确列出的 2 个一级功能、6 个二级功能、16 个三级功能和四级功能清单。

本规格将前端从“大页摘要”调整为“四级功能独立页面”：一级、二级、三级承担导航归属，四级功能承担主内容视图。用户先进入登录页，登录后的默认着陆页是项目列表；从项目列表选择项目后进入当前功能导航页。页面标题显示三级功能名称；非建模页面右上角显示当前方案名称，点击后回到对应模块的方案列表。

## 目标

1. 按概要设计表 2 的四级功能清单完整展开页面结构。
2. 每个四级功能拥有独立页面视图和可导航地址。
3. 通过页面模板复用降低实现重复，而不是为每个四级页面手写一套实现。
4. 仿真建模和仿真实验页面不再显示“xxx入口”卡片，四级功能切换使用紧凑中文标签；可视化推演直接嵌入 Mesa 可视化页面，不再显示外层四级导航。
5. 结果分析中的备件短板分析、飞机转场携行清单分析、任务可靠度评估、停机因素分析对齐 `vendor/ship_front/备件_front` 的静态分析页结构。
6. 保障组织建模和保障活动建模对齐 `vendor/ship_front` 的树表编辑、方案列表、作业项和网络图布局。
7. 蒙特卡洛实验配置页只保留参数配置和启动入口；点击启动后返回仿真实验方案列表，并将对应方案状态置为“运行中”。蒙特卡洛评估结果统一迁移到 `结果分析 / 蒙特卡洛实验结果展示`。
8. 保持当前静态前端和本地仿真原型边界，不在本次设计中引入后端、权限系统或真实长任务调度。

## 非目标

1. 不实现完整 Web 平台、用户权限、模板/项目/方案数据权限。
2. 不把小样本原型结果表述为工程级最优方案。
3. 不在本设计阶段修改 Mesa 模型规则或实验算法。
4. 不把全部四级页面都做成完全不同的定制实现。

## 推荐方案

采用“A + C”方案：

- 信息架构采用严格四级功能页矩阵：一级模块、二级功能、三级分组、四级页面。
- 工程实现采用模板化页面系统：用功能清单配置驱动四级页面，复用字段表单、关系图、状态机、可靠性框图、甘特、结果表、指标条、校验面板等组件。

这样用户看到的是完整的功能页体系，工程上仍能保持可维护性。

## 信息架构

页面结构采用四层：

1. 一级功能：`备件规划评估模块`、`任务可靠度评估模块`。
2. 二级功能：`仿真建模`、`仿真实验`、`结果分析`。
3. 三级功能：例如 `任务建模`、`装备建模`、`保障组织建模`、`保障活动建模`。
4. 四级功能：真正可进入的页面视图。

入口流转为：登录页 -> 项目列表页 -> 功能导航页。项目列表承载登录后的首屏选择，功能导航页继续保留左侧一级到三级层级。一级模块作为大分区，二级功能作为折叠组，三级功能作为可点击入口。进入三级功能后，主内容区直接显示该组的四级页面；当同组存在多个四级功能时，用紧凑中文标签切换，不再渲染“xxx入口”卡片或英文组件名。

### 源文档计数差异

`docs/3概要设计方案.md` 正文写明“47 个四级功能”，表 2 原始转换稿列出 49 行四级功能。当前实现按可达页面口径保留 49 个页面：将原“仿真实验方案创建/编辑”产品口径调整为“方案列表/方案编辑”；将原“任务剖面建模”拆为“任务剖面参数”“复合任务建模”“周期性任务建模”；将原保障活动方案页调整为“基本保障活动建模”“使用保障活动建模”“预防性维修活动建模”“修复性维修活动建模”；并将可视化推演下的启动停止、场景切换和结果展示合并为一个可导航入口，因为这些能力已经在 Mesa 页面内部完成。旧的场景切换、可视化结果展示 hash 仅作为兼容别名回流到可视化推演。

## 页面模板

每个四级页面采用一致骨架：

1. 页面标题区：显示三级功能名称、一级到三级归属路径；非建模页面显示当前方案名称，当前方案名称可点击进入方案列表。
2. 左侧导航区：显示一级到三级功能树，当前三级功能高亮。
3. 主编辑区：承载当前功能的核心输入、图形、表格或控制面板。
4. 四级标签区：仅在仿真建模和仿真实验的多四级功能组中显示，标签高度收窄且只显示中文功能名；可视化推演不显示该外层标签区。

### 主编辑区类型

| 功能类型 | 主编辑组件 |
| --- | --- |
| 任务建模 | 表单、任务层级树、任务阶段状态机 |
| 装备建模 | 装备组成树、故障参数表、可靠性框图 |
| 保障组织建模 | 保障组织树、库存表、人员/设备能力表 |
| 保障活动建模 | 活动树、工作项目清单、活动节点网络图 |
| 仿真实验方案 | 方案列表、方案编辑、参数表、方案摘要 |
| 可视化推演 | Mesa 页面内的运行控制、场景视图、事件流、指标条 |
| 蒙特卡洛实验 | 扫参配置、样本摘要、结果表 |
| 结果分析 | 排名表、指标分解、因素贡献图 |

### 外部原型对齐

1. `vendor/ship_front` 提供舰载机保障建模页参考。保障组织建模采用其左侧树、右侧详情表和资源维护布局；保障活动建模采用其方案列表、基本保障活动作业项表和节点网络图布局。
2. `vendor/ship_front` 也提供蒙特卡洛实验页参考。当前实现仅保留其参数配置和启动动作形态，不保留主页签、正交实验入口或预检查按钮。
3. `vendor/ship_front/备件_front` 提供四个结果分析页参考。备件短板分析、飞机转场携行清单分析、任务可靠度评估、停机因素分析采用相同的启动/筛选、指标卡、表格、图示和决策建议结构；携行清单页保留优化目标、满足率和利用率约束。
4. 这些参考仅作为本仓库静态前端的页面形态来源，运行时代码不依赖 `vendor/ship_front` 或 `vendor/ship_front/备件_front` 的脚本。

## Ontology 关系视图与上下文数据

> M5 当前口径：本节早期的 Mesa `Ontology视图` 约定已过期。`docs/ontology-mesa-rebuild-plan.md` 已移动到 `docs/archive/deprecated/ontology-mesa-rebuild-plan.md`，仅作历史参考。当前产品路线不再要求在 Mesa 仿真中展示 ontology 视图。

本规格早期使用过三层口径：

| 层级 | 含义 |
| --- | --- |
| `modeling-object` | 任务、装备、保障、备件和指标分配等可编辑建模对象。 |
| `simulation-experiment` | 实验方案、想定、可视化运行控制和 Monte Carlo 配置。 |
| `computation-artifact` | 运行数据、指标时间序列、聚合摘要、短板/携行/可靠度/停机因素分析结果。 |

该三层描述曾被早期四层纵向画布约定取代，但该四层约定现已归档过期：

| 层级 | 含义 |
| --- | --- |
| 建模对象 | 与前端四级功能、页面 `dataObjects` 和 project JSON 字段路径对齐。 |
| 仿真实验 | 描述实验方案、想定、扫参、seed/sample、停止条件和运行请求。 |
| 模型实例 | 按 `AviationSupportModel` 的真实 Mesa agent 或 Python domain object 绘制运行时对象关系，并包含当前 step 的指标对象。 |
| 计算产物 | 描述运行数据集、指标时间序列、summary 和结果分析产物。 |

实际可见行为：

1. `可视化推演` 仍是唯一可导航入口。
2. Mesa 页面产品口径保留飞机、任务、保障等状态视图。
3. Mesa 内部 `Ontology视图` 不再作为当前产品能力或验收口径。
4. `front/ontology-context.mjs` 可继续作为测试、导出或历史兼容辅助存在，但不代表可见页面必须渲染 ontology 图谱。

关系标签以当前项目级图谱为准，例如 `包含`、`要求`、`部署在`、`隶属于`、`安装在`、`导入约束`、`引用`、`驱动`、`启动停止`、`观察`、`批量生成`、`保存`、`逐步计算`、`聚合`、`支撑`。不要再使用旧设计中的 `depends_on`、`writes_to`、`drives`、`validates`、`shares_with` 作为已实现 UI 关系标签。

## 数据流

页面仍围绕单一前端场景状态工作。四级页面不复制私有状态，而是读写同一个 scenario/project JSON。

1. 导航选择四级功能。
2. 页面配置读取当前 scenario 对应数据对象。
3. 用户编辑字段、关系、表格或图节点。
4. 页面即时更新共享 scenario。
5. 页面校验器运行并返回问题列表。
6. 相关页面通过共享数据看到同一结果。
7. 运行单次仿真或蒙特卡洛时，从共享 scenario 生成实验输入。

这延续当前前端原型的约束：所有页面消费同一份项目状态，跨页面切换后编辑结果仍可见。

## 错误处理

1. 缺失字段：在校验区显示字段路径和中文说明。
2. 关系端点缺失：由页面校验区或后端应用校验返回字段路径和引用问题；Mesa ontology 图谱不承担每页内联报错。
3. 参数超出范围：阻止保存该字段并提示允许范围。
4. 页面没有专属数据时：显示空状态和可创建入口，不降级成空白页。
5. 仿真输入不完整：实验页面显示阻塞原因，不启动运行。
6. 前端脚本加载失败：保留现有可见错误兜底，避免停留在静默加载状态。

## 实现边界建议

后续实现可拆为三层：

1. `feature-catalog`：声明表 2 列出的四级页面、归属路径、数据对象和组件类型。
2. `feature-router`：根据当前功能 ID 渲染页面，并维护导航高亮。
3. `feature-page-template`：渲染标题、主编辑区、校验区和输出摘要。
4. `ontology-context`：仅作为项目级 ontology、页面 focus context 辅助和 Ontology Playground 导出形态的历史兼容模块；当前产品不要求可见图谱消费它。

现有 `front/app.js` 已经过长，实际实现时应优先拆分配置和渲染模块，避免继续把全部四级页面逻辑堆入单文件。

## 验收标准

1. 前端导航可访问所有列入清单的四级页面。
2. 每个非可视化四级页面都有独立标题、归属路径和当前页面高亮；可视化推演不显示“可视化实验启动与停止”外层标题。
3. 用户打开前端先进入登录页，登录后进入项目列表；从项目列表进入功能导航页。
4. 三级页面右上角方案名可点击返回方案列表，顶部项目名称可回到项目列表。
5. 页面清单由集中配置驱动，测试能验证页面数量、功能 ID 唯一性和导航可达性。
6. 仿真建模和仿真实验页面不再出现“xxx入口”框，四级标签不显示英文组件名。
7. 共享 scenario 数据在相关页面之间保持一致。
8. 关键页面至少覆盖当前原型已有能力：任务建模、装备故障、可靠性框图、保障活动甘特、Mesa 可视化、蒙特卡洛、结果分析。
9. 两个模块的四个指定结果分析页呈现 `@备件_front` 风格的独立分析面板。
10. 保障组织建模和保障活动建模呈现 `vendor/ship_front` 风格的树表编辑和活动网络结构。
11. 蒙特卡洛实验配置页只读展示当前仿真实验，并呈现仿真次数、随机种子和扫参配置；点击启动后回到方案列表并显示“运行中”，蒙特卡洛评价结果只在结果分析页展示。
12. 页面侧 `Ontology 上下文` 面板、独立 ontology 可视化路由和 Mesa 内部 `Ontology视图` 均不再作为当前产品验收口径。
13. `npm test` 通过，并新增或更新前端结构测试覆盖登录、项目列表、结果分析页、保障组织/活动建模、蒙特卡洛实验页、紧凑四级标签、页面侧上下文面板移除和 Mesa 可视化直嵌。
