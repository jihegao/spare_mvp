分层职责

输入参数层

正式 single run 的业务输入来自已发布导入包生成的 Project、实验方案分支和 RunIntent。

  • tests/fixtures/modeling_import_project.json 是完整业务示例源。
  • ExperimentPlan.config.projectJson 优先于旧 snapshot 回退。
  • run_type 在 M9.7.2 固定关注 single。

编译与治理层

SimulationAdapter.compile_scenario_with_gate() 是 Project 到 Scenario 的正式入口。

  • 输出 AircraftSupportV1Model Scenario envelope。
  • simulation_inputs 必须符合独立 input schema。
  • mapping_provenance 记录 consumed、derived、defaulted、governance_only、unsupported。

正式运行层

RunService.submit_run() 负责身份链、run id、Scenario 持久化和失败编译落库。

  • 入口必须是 canonical POST /api/runs。
  • 正式 run 需要 imported sample 来源审计通过。
  • 失败编译返回 failed status envelope，不伪造 result。

仿真内核层

M9.7.2 新增 src/spare_mvp_abm/aircraft_support_v1/ runtime。

  • 固定 seed 下可复现。
  • 分钟级 tick，固定事件阶段顺序。
  • 每 30 分钟输出可视化状态帧。

结果输出层

single run 输出必须足够支撑结果审计、状态回放和后续分析接入。

  • result_summary、metrics、report、log。
  • artifact_manifest 记录每个 artifact 的 kind/schema/path/hash。
  • visualization_state_series 包含 run/result/manifest/Scenario traceability。

关键 payload 映射

编译后 input payload

  • project_identity: project id、version、scenario id、source import id。
  • mission_profile: 任务、阶段、机场、任务区和 duration。
  • aircraft: 机队规模、初始可用数和机型。
  • equipment_tree: LRU/组件、数量和故障率。
  • support_network: 保障节点、人员/设备能力、库存、运输策略。
  • support_activities: 活动 DAG、资源引用、工序。
  • time: tick_minutes=1、sample_every_minutes=30。
  • seed: single run 可复现随机源。

single run 输出包

  • run: run id、scenario id、model family、status、result id、artifact manifest id。
  • result: 指标摘要和模型族专属 metrics。
  • artifact_manifest: run config、input project、compiled Scenario、metrics、report、log、state-series。
  • visualization_state_series: 帧、事件摘要、metric refs、run/result/manifest/Scenario 追溯字段。
  • run chain: 通过 repository 和 artifact id 支撑前端状态、回放和审计。

阻断边界

M9.7.2 的目标不是让页面在任何输入下都有看似成功的输出，而是在正式输入链路不成立时明确 fail closed。 缺少 compiler provenance、非法引用、缺少 visualization_state_series、unsupported 字段族仍影响正式运行、 或绕过 canonical /api/runs 的路径，都不能显示为正式后端仿真结果。
