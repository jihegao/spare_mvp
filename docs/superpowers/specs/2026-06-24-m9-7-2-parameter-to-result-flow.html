AircraftSupportV1Model 内核展开图

这张图把编译后的 simulation_inputs 展开到模型对象和对象字段，再连接到 single run 输出对象。 对象名和方法名以当前 src/spare_mvp_abm/aircraft_support_v1/model.py 实现为准； 下方另列仍出现在早期图中的过期概念方法名。

实际行为驱动字段
  • aircraft.fleet_count、initial_ready、models 生成 AircraftState[]。
  • mission_profile.basic_mission、composite_tasks[]、periodic_tasks[] 生成 MissionState[]。
  • mission_phases[]、airports[]、mission_areas[] 通过 _mission_context() 调整任务时长。
  • equipment_tree.components[]、reliability_block_diagram 生成故障率、寿命压力、维修时长和备件需求。
  • support_network.nodes[] 的人员/设备能力、库存和运输策略约束作业启动。
  • support_activities.activities[].jobs[] 和 predecessors 决定保障作业顺序。
  • time.duration_minutes、tick_minutes、sample_every_minutes、max_state_frames_single 控制循环和采样。
  • seed 驱动 random.Random，保证故障抽样可复现。
实际运行方法
  • 加载: __init__()、_build_aircraft()、_behavior_components()、_build_support_nodes()、_build_activities()、_build_missions()。
  • 任务: _create_due_preflight_jobs()、_dispatch_due_missions()、_mission_preflight_commissioned_count()。
  • 保障: _create_job()、_start_waiting_jobs()、_process_arrivals_and_completions()、_complete_job_effect()。
  • 资源: _task_spare_requirement()、_try_transport_replenishment()、_consume_task_spare()、_release_job_resources()。
  • 故障: _evaluate_failures()、_effective_component_failure_rate()、_component_repair_duration_minutes()、_rbd_components()。
  • 输出: snapshot()、visualization_frame()、_events_for_frame()、behavior_scope()。
过期或仅历史参考的方法名
  • buildMissionSchedule()、buildAircraftAgents()、buildComponentStates()、buildSupportDag() 是早期图中概念名，不是当前 Python 方法。
  • dispatch_phase()、failure_phase()、support_phase()、metrics_phase() 已替换为 run() 内固定方法序列。
  • FrameBuilder、MetricsAccumulator、SnapshotBuilder 是旧图层命名；当前实现使用 visualization_frame() 和 snapshot()。
  • evaluateRbd() 当前不是独立方法；RBD 节点通过 _rbd_components() 转成附加故障组件。
  • supportOrganization.tree 是 governance-only / 不驱动仿真字段，不再作为 fail closed 条件。
  • 独立 postflight 或 preventive 作业触发方法当前不存在；相关输入保留在保障活动数据和后续覆盖语义中。

执行时序图

两个时序图都按当前 AircraftSupportV1Model 代码路径展开。虚线/红色步骤表示业务期望或历史模型中出现过， 但当前 aircraft_support_v1 内核尚未作为独立状态或方法实现。

1. 仿真对象加载顺序

复制输入并建立随机源self.inputs、seed、random.Random(seed)。
读取时钟配置duration_minutes、tick_minutes=1、sample_every_minutes、max_state_frames_single。
初始化事件和飞机event_log 后调用 _build_aircraft() 生成 AircraftState[]。
生成故障组件_behavior_components() 读取装备树，并合并 _rbd_components()。
加载保障资源_build_support_nodes() 生成容量、库存、运输策略和占用计数。
加载保障活动_build_activities() 和 _ordered_activity_jobs() 排序 job DAG。
生成任务上下文_mission_context() 用机场、任务区和阶段推导时长修正。
选择飞前和维修活动_select_activity("preflight")、_select_activity("repair")，缺省时回退 _default_activity()。
生成任务实例和计数器_build_missions() 创建 MissionState[]，再初始化 jobs 和指标计数。

2. 仿真推演过程

任务准备窗口到时_create_due_preflight_jobs() 检查 preparation_start 和任务所需飞机数。
寻找任务成员飞机从 AircraftState.state == "available" 且未为该任务准备的飞机中挑选。
飞机进入准备飞机临时置为 maintenance，通过 _create_job(kind="preflight") 生成飞前保障作业。
生成保障作业执行计划和资源JobState.tasks 复制活动 jobs，绑定 resource_node_id、优先级、任务 id 和飞机号。
保障执行_start_waiting_jobs() 校验人员/设备/备件；必要时 _try_transport_replenishment() 调拨库存。
完成保障_process_arrivals_and_completions() 扣减剩余时间、释放资源、消耗备件并调用 _complete_job_effect()。
任务通知飞机起飞_dispatch_due_missions() 查找已准备飞机，置为 flying 并记录 return_time。
任务结束返航当前时间达到 return_time 时，_process_arrivals_and_completions() 将飞机转回 available。
故障转维修_evaluate_failures() 对可用飞机抽样；命中后置为 maintenance 并生成 repair 作业。
飞行后保障 / 预防性维修当前 aircraft_support_v1 没有独立 postflight 或 preventive 触发方法；不要把旧业务流程图解读为已执行逻辑。
回到待命状态并采样飞前或维修作业完成后转 available；到采样点时输出 visualization_frame()。

分层职责

输入参数层

正式 single run 的业务输入来自已发布导入包生成的 Project、实验方案分支和 RunIntent。

  • tests/fixtures/modeling_import_project.json 是完整业务示例源。
  • ExperimentPlan.config.projectJson 优先于旧 snapshot 回退。
  • run_type 在 M9.7.2 固定关注 single。

编译与治理层

SimulationAdapter.compile_scenario_with_gate() 是 Project 到 Scenario 的正式入口。

  • 输出 AircraftSupportV1Model Scenario envelope。
  • simulation_inputs 必须符合独立 input schema。
  • mapping_provenance 记录 consumed、derived、defaulted、governance_only、unsupported。

正式运行层

RunService.submit_run() 负责身份链、run id、Scenario 持久化和失败编译落库。

  • 入口必须是 canonical POST /api/runs。
  • 正式 run 需要 imported sample 来源审计通过。
  • 失败编译返回 failed status envelope，不伪造 result。

仿真内核层

M9.7.2 新增 src/spare_mvp_abm/aircraft_support_v1/ runtime。

  • 固定 seed 下可复现。
  • 分钟级 tick，固定事件阶段顺序。
  • 每 30 分钟输出可视化状态帧。

结果输出层

single run 输出必须足够支撑结果审计、状态回放和后续分析接入。

  • result_summary、metrics、report、log。
  • artifact_manifest 记录每个 artifact 的 kind/schema/path/hash。
  • visualization_state_series 包含 run/result/manifest/Scenario traceability。

关键 payload 映射

编译后 input payload

  • project_identity: project id、version、scenario id、source import id。
  • mission_profile: 任务、阶段、机场、任务区和 duration。
  • aircraft: 机队规模、初始可用数和机型。
  • equipment_tree: LRU/组件、数量和故障率。
  • support_network: 保障节点、人员/设备能力、库存、运输策略。
  • support_activities: 活动 DAG、资源引用、工序。
  • time: tick_minutes=1、sample_every_minutes=30。
  • seed: single run 可复现随机源。

single run 输出包

  • run: run id、scenario id、model family、status、result id、artifact manifest id。
  • result: 指标摘要和模型族专属 metrics。
  • artifact_manifest: run config、input project、compiled Scenario、metrics、report、log、state-series。
  • visualization_state_series: 帧、事件摘要、metric refs、run/result/manifest/Scenario 追溯字段。
  • run chain: 通过 repository 和 artifact id 支撑前端状态、回放和审计。

阻断边界

M9.7.2 的目标不是让页面在任何输入下都有看似成功的输出，而是在正式输入链路不成立时明确 fail closed。 缺少 compiler provenance、非法引用、缺少 visualization_state_series、unsupported 字段族仍影响正式运行、 或绕过 canonical /api/runs 的路径，都不能显示为正式后端仿真结果。
