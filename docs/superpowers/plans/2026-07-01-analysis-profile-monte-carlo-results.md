# 分析参数空间蒙特卡洛结果计划草案

## 目标

在当前只开放一个默认基础方案的前提下，统一可视化推演、蒙特卡洛实验页和四个分析页的结果所有权：

- 一个 Project 当前只有一个默认基础方案。
- 默认基础方案以建模 Project 数据的快照语义生成和保存。
- 可视化推演、蒙特卡洛实验页和四个分析页都消费同一个默认基础方案。
- 每个页面只保留一个当前结果，再次运行只替换对应当前结果。
- 用户不需要感知内部绑定、artifact 或 run chain 概念。

## 产品契约

- 当前只开放一个默认基础方案，不开放多方案编辑。
- 可视化推演只保留一个当前推演结果。
- 蒙特卡洛实验页只保留一个“蒙特卡洛实验页当前评估结果”。
- 四个分析页各自只保留一个当前分析结果。
- 四个分析页共享同一个基础方案，但各自拥有独立参数探索空间。
- 四个分析页不共享同一次蒙特卡洛运行。
- 重新运行某一页，只替换该页自己的当前结果。
- 刷新或重建基础方案后，所有已存在结果都应变为过期状态，等待重新运行。
- 失败运行不生成新的用户可见历史结果；页面只展示当前结果状态和错误信息。

## 2026-07-02 实现状态

- 已完成四个结果分析页的第一片 current profile/current result 主流程：页面展示当前参数空间、当前结果状态和运行入口，不再把 AnalysisTask 列表、MC 绑定、run 或 artifact 选择作为普通用户主流程。
- 当前 profile 通过 `ExperimentPlan.config.analysisType`、`scenarioOverrides` 和 carry-list-only `carryListConfig` 进入 canonical `/api/runs`；`/api/runs` request body 不承载这些页面参数。
- 后端只在 Scenario compiler 之后、Scenario 持久化和 adapter 执行之前应用 run-scoped override：`scenarioOverrides.sparesBySupportPoint[]` 改写 compiled support node inventory，`scenarioOverrides.missionDurationMinutes` 改写 compiled mission/time duration。
- override traceability 写入 compiled Scenario、compiler provenance、run_config、`monte_carlo_base` 和对应 projection payload；Project、ModelingSnapshot 和 imported JSON 不被改写。
- `carryListConfig.missionConfidenceTarget` 只允许 `analysisType = "carry_list"` 使用，并进入 carry-list projection 的 KPI 和表格字段。
- 尚未完成六个 current result slot 的持久化、默认基础方案刷新后的 stale 传播、上一条成功结果保留和失败不覆盖策略；这些仍按本计划后续 P4/P7 收口。

## 结果数量边界

在只有一个默认基础方案时，产品层最多展示 6 个当前结果：

- 1 个可视化推演结果。
- 1 个蒙特卡洛实验页当前评估结果。
- 1 个备件短板分析结果。
- 1 个飞机转场携行清单分析结果。
- 1 个任务可靠度评估结果。
- 1 个停机因素分析结果。

这些结果是当前状态，不是历史列表。

## 页面语义

### 可视化推演

- 页面展示“当前推演结果”。
- 启动新仿真后，当前推演结果被替换。
- 不提供历史回放入口。
- 不提供旧 run 选择入口。
- 可以展示当前结果来源、状态、关键指标和事件摘要。

### 蒙特卡洛实验

- 页面展示“蒙特卡洛实验页当前评估结果”。
- 结果基于默认基础方案。
- 默认参数空间是单点基线评估：`failureRates` 和 `spareMultipliers` 使用 `1.0` multiplier，`supportCapacities` 来自当前建模产物的保障资源能力。
- 默认蒙特卡洛实验页不主动引入 failure rate / spare multiplier / support capacity 的多点 sweep。
- 重新运行后替换“蒙特卡洛实验页当前评估结果”。
- 不展示历史实验列表。
- 不要求用户选择或绑定 MC 实验。

### 四个分析页

- 页面展示各自的“参数探索空间”和“当前分析结果”。
- 每个分析页都有独立参数空间。
- 只有四个分析页的参数探索空间需要表达多点 sweep；多点参数探索不回流为默认蒙特卡洛实验页的默认行为。
- 每个分析页重新运行时，只替换自己的当前分析结果。
- 不要求用户手动绑定蒙特卡洛实验。
- 不展示内部运行 ID 作为主工作流信息。

四个分析类型为：

- 备件短板分析。
- 飞机转场携行清单。
- 任务可靠度评估。
- 停机因素分析。

## 数据与保存边界

- 默认基础方案需要持久化。
- 四个分析页的参数探索空间需要持久化。
- 六个当前结果需要持久化或可恢复为当前状态。
- 产品层不保存多版本结果历史。
- 内部可保留运行记录、artifact 和追溯信息用于调试、审计和测试，但不能变成用户可见历史结果。
- 可视化推演不进入四个分析页的结果模型。
- “蒙特卡洛实验页当前评估结果”不属于四个分析 profile。

## 后台自动化边界

- 系统应在后台自动保证默认基础方案存在。
- 系统应在后台自动保证四个分析页的参数空间存在。
- 用户进入页面时，不应看到“创建方案”“绑定 MC”“选择 artifact”这类内部步骤。
- 用户点击运行后，系统自动使用当前基础方案和对应页面参数空间。
- 用户只看到运行状态、当前结果、过期状态和错误状态。

## 状态规则

- `empty`: 当前页尚无结果。
- `running`: 当前页正在生成结果。
- `completed`: 当前页已有可用结果。
- `stale`: 基础方案或参数空间已变化，当前结果需要重跑。
- `failed`: 最近一次运行失败，页面展示失败状态和可重试入口。

状态名称可以在实现时映射为现有系统字段，但产品语义必须保持一致。

## 影响范围

### 后端

- 默认基础方案生命周期。
- 分析参数空间生命周期。
- 当前结果保存与替换规则。
- 基础方案刷新后的结果过期规则。
- 运行失败后的当前结果状态表达。

### 前端

- 可视化推演页改为单一当前结果视图。
- 蒙特卡洛实验页改为单一“蒙特卡洛实验页当前评估结果”视图。
- 四个分析页改为各自参数空间和当前结果视图。
- 移除用户可见的绑定、历史列表和回放选择主流程。
- 保留必要的调试信息，但不得干扰主流程。

### 文档

- README、agent 文档和产品路线图需要同步新的结果所有权。
- 文档中应明确只有一个基础方案时的 6 个当前结果边界。
- 文档中应明确内部运行追溯不等于用户可见历史结果。

## 验收标准

- 新建或导入项目后，系统能自动得到一个默认基础方案。
- 进入可视化推演页，不需要先手动创建方案或选择历史 run。
- 可视化推演运行两次后，页面只展示第二次运行的当前结果。
- 进入蒙特卡洛实验页，不需要手动绑定实验。
- 默认蒙特卡洛实验页生成的参数空间只有一个基线组合，且 multiplier 类参数为 `1.0`。
- 默认蒙特卡洛实验页的 support capacity 基线来自建模产物，而不是固定常量。
- 蒙特卡洛实验运行两次后，页面只展示第二次运行的“蒙特卡洛实验页当前评估结果”。
- 四个分析页都能基于同一个基础方案运行。
- 任意一个分析页运行两次后，该分析页只展示第二次运行的当前结果。
- 任意一个分析页重跑，不影响另外三个分析页的当前结果。
- 修改某个分析页参数空间，只让该分析页结果过期。
- 刷新基础方案后，可视化、蒙特卡洛和四个分析结果全部过期。
- 用户主界面不出现“绑定 MC 实验”“选择 artifact”“保存全部历史结果”这类内部语义。
- 测试覆盖可证明产品层不会出现多条用户可见历史结果。

## 非目标

- 本阶段不开放多个用户可编辑实验方案。
- 本阶段不开放实验方案参数编辑界面。
- 本阶段不做用户可见历史结果列表。
- 本阶段不做可视化历史回放管理。
- 本阶段不让四个分析页共享同一次变参数 MC 结果。
- 本阶段不移除内部运行追溯能力。

## 前置依赖与阻塞关系

- 必须先完成 run intent 到当前建模快照、默认基础方案和运行链路的身份一致性修复。当前进行中的 PR #106 属于该前置依赖：它应先保证新保存的 Project 输入、建模快照、实验方案和提交运行之间不会错绑旧快照。
- PR #106 中的修复性维修活动 host 调整不是本计划的结果所有权 blocker。若 PR #106 因该部分变更卡住，应优先拆出并合并身份链修复，再让维修活动 host 修复并行推进。
- 本计划以“产品主流程只展示六个当前结果”为准。旧文档中关于用户手动选择 Monte Carlo、绑定 artifact 或查看分析任务历史的描述，只保留为内部追溯或后续多方案阶段的参考，不进入本阶段主流程。
- 后端 contract 必须先于页面改造落地；否则六个页面容易各自实现一套 current result 语义，造成后续返工。

## 推荐实施顺序

1. **P0：合并或拆分前置身份链修复。** 先让当前 Project 输入、建模快照、默认基础方案和运行链路保持一致；如果 PR #106 继续包含非阻塞变更，应优先拆出身份链部分。
2. **P1：固化结果所有权 contract。** 明确一个默认基础方案、六个 current result slot、五种状态、过期规则和用户不可见的内部概念。
3. **P2：实现默认基础方案生命周期。** 新建、导入或进入页面时自动保证默认基础方案存在；刷新或重建基础方案时使六个当前结果全部过期。
4. **P3：实现四个分析页参数空间生命周期。** 四个分析页共享同一个基础方案，但各自保存独立参数空间；修改某个参数空间只让该页结果过期。
5. **P4：实现当前结果保存与替换语义。** 每个结果 slot 只保留一个产品可见当前状态；成功运行替换该 slot，失败运行只更新失败状态和错误信息。
6. **P5：实现运行编排入口。** 用户点击运行时，系统自动使用当前基础方案和对应页面参数空间，并把内部 run、result、artifact 映射回对应 current result slot。
7. **P6：改造前端主流程。** 六个页面统一使用 current result 视图，移除用户可见的绑定、历史列表、回放选择和 artifact 选择入口；调试信息只能作为辅助入口展示。
8. **P7：同步文档并做端到端验收。** 验证六个页面的当前结果、重跑替换、局部过期、全局过期、失败重试和内部追溯边界。

## 可并行任务

- PR #106 中非阻塞的维修活动 host 修复可以与本计划文档、contract 梳理并行。
- 旧 M6.2、M7.0、README、agent 文档和 roadmap 中涉及“用户可见历史 / 绑定 artifact / 选择 run”的表述可以提前梳理，但最终改文档应以本计划的 current result contract 为准。
- 四个分析页的参数空间 schema 可以在 P1 contract 稳定后并行设计，但 profile key、版本号和 stale 规则必须统一。
- 六个前端页面的文案清理可以提前做清单；真正接入 API 应等 P5 运行编排入口稳定后再并行实施。
- 端到端验收用例可以在 P1 后提前设计；真正跑通应等 P6 页面改造完成后收口。

## 暂不建议优先做

- 不优先做用户可见 run 历史、artifact 选择器、Monte Carlo 绑定列表或多版本结果列表。
- 不优先扩展多方案编辑、实验方案参数编辑界面或可视化历史回放管理。
- 不把内部运行追溯能力删除；只是不让它成为用户主流程。
- 不让四个分析页共享同一次变参数 Monte Carlo 结果，也不把“蒙特卡洛实验页当前评估结果”混入四个分析 profile。
