# 分析参数空间蒙特卡洛结果计划草案

## 目标

在当前只开放一个默认基础方案的前提下，统一可视化推演、蒙特卡洛实验页和四个分析页的结果所有权：

- 一个 Project 当前只有一个默认基础方案。
- 默认基础方案以建模 Project 数据的快照语义生成和保存。
- 可视化推演、蒙特卡洛实验页和四个分析页都消费同一个默认基础方案。
- 每个页面只保留一个当前结果，再次运行只替换对应当前结果。
- 用户不需要感知内部绑定、artifact 或 run chain 概念。

## 产品契约

- 当前只开放一个默认基础方案，不开放多方案编辑。
- 可视化推演只保留一个当前推演结果。
- 蒙特卡洛实验页只保留一个“蒙特卡洛实验页当前评估结果”。
- 四个分析页各自只保留一个当前分析结果。
- 四个分析页共享同一个基础方案，但各自拥有独立参数探索空间。
- 四个分析页不共享同一次蒙特卡洛运行。
- 重新运行某一页，只替换该页自己的当前结果。
- 刷新或重建基础方案后，所有已存在结果都应变为过期状态，等待重新运行。
- 失败运行不生成新的用户可见历史结果；页面只展示当前结果状态和错误信息。

## 结果数量边界

在只有一个默认基础方案时，产品层最多展示 6 个当前结果：

- 1 个可视化推演结果。
- 1 个蒙特卡洛实验页当前评估结果。
- 1 个备件短板分析结果。
- 1 个飞机转场携行清单分析结果。
- 1 个任务可靠度评估结果。
- 1 个停机因素分析结果。

这些结果是当前状态，不是历史列表。

## 页面语义

### 可视化推演

- 页面展示“当前推演结果”。
- 启动新仿真后，当前推演结果被替换。
- 不提供历史回放入口。
- 不提供旧 run 选择入口。
- 可以展示当前结果来源、状态、关键指标和事件摘要。

### 蒙特卡洛实验

- 页面展示“蒙特卡洛实验页当前评估结果”。
- 结果基于默认基础方案。
- 重新运行后替换“蒙特卡洛实验页当前评估结果”。
- 不展示历史实验列表。
- 不要求用户选择或绑定 MC 实验。

### 四个分析页

- 页面展示各自的“参数探索空间”和“当前分析结果”。
- 每个分析页都有独立参数空间。
- 每个分析页重新运行时，只替换自己的当前分析结果。
- 不要求用户手动绑定蒙特卡洛实验。
- 不展示内部运行 ID 作为主工作流信息。

四个分析类型为：

- 备件短板分析。
- 飞机转场携行清单。
- 任务可靠度评估。
- 停机因素分析。

## 数据与保存边界

- 默认基础方案需要持久化。
- 四个分析页的参数探索空间需要持久化。
- 六个当前结果需要持久化或可恢复为当前状态。
- 产品层不保存多版本结果历史。
- 内部可保留运行记录、artifact 和追溯信息用于调试、审计和测试，但不能变成用户可见历史结果。
- 可视化推演不进入四个分析页的结果模型。
- “蒙特卡洛实验页当前评估结果”不属于四个分析 profile。

## 后台自动化边界

- 系统应在后台自动保证默认基础方案存在。
- 系统应在后台自动保证四个分析页的参数空间存在。
- 用户进入页面时，不应看到“创建方案”“绑定 MC”“选择 artifact”这类内部步骤。
- 用户点击运行后，系统自动使用当前基础方案和对应页面参数空间。
- 用户只看到运行状态、当前结果、过期状态和错误状态。

## 状态规则

- `empty`: 当前页尚无结果。
- `running`: 当前页正在生成结果。
- `completed`: 当前页已有可用结果。
- `stale`: 基础方案或参数空间已变化，当前结果需要重跑。
- `failed`: 最近一次运行失败，页面展示失败状态和可重试入口。

状态名称可以在实现时映射为现有系统字段，但产品语义必须保持一致。

## 影响范围

### 后端

- 默认基础方案生命周期。
- 分析参数空间生命周期。
- 当前结果保存与替换规则。
- 基础方案刷新后的结果过期规则。
- 运行失败后的当前结果状态表达。

### 前端

- 可视化推演页改为单一当前结果视图。
- 蒙特卡洛实验页改为单一“蒙特卡洛实验页当前评估结果”视图。
- 四个分析页改为各自参数空间和当前结果视图。
- 移除用户可见的绑定、历史列表和回放选择主流程。
- 保留必要的调试信息，但不得干扰主流程。

### 文档

- README、agent 文档和产品路线图需要同步新的结果所有权。
- 文档中应明确只有一个基础方案时的 6 个当前结果边界。
- 文档中应明确内部运行追溯不等于用户可见历史结果。

## 验收标准

- 新建或导入项目后，系统能自动得到一个默认基础方案。
- 进入可视化推演页，不需要先手动创建方案或选择历史 run。
- 可视化推演运行两次后，页面只展示第二次运行的当前结果。
- 进入蒙特卡洛实验页，不需要手动绑定实验。
- 蒙特卡洛实验运行两次后，页面只展示第二次运行的“蒙特卡洛实验页当前评估结果”。
- 四个分析页都能基于同一个基础方案运行。
- 任意一个分析页运行两次后，该分析页只展示第二次运行的当前结果。
- 任意一个分析页重跑，不影响另外三个分析页的当前结果。
- 修改某个分析页参数空间，只让该分析页结果过期。
- 刷新基础方案后，可视化、蒙特卡洛和四个分析结果全部过期。
- 用户主界面不出现“绑定 MC 实验”“选择 artifact”“保存全部历史结果”这类内部语义。
- 测试覆盖可证明产品层不会出现多条用户可见历史结果。

## 非目标

- 本阶段不开放多个用户可编辑实验方案。
- 本阶段不开放实验方案参数编辑界面。
- 本阶段不做用户可见历史结果列表。
- 本阶段不做可视化历史回放管理。
- 本阶段不让四个分析页共享同一次变参数 MC 结果。
- 本阶段不移除内部运行追溯能力。

## 推荐实施顺序

1. 固化默认基础方案和结果所有权规则。
2. 固化四个分析页的参数空间边界。
3. 调整后端当前结果保存与替换语义。
4. 调整前端页面文案和主流程。
5. 补齐状态展示、过期提示和失败重试。
6. 同步文档。
7. 做端到端验收。

## 待确认问题

- 刷新基础方案是否需要用户确认，还是由导入或建模保存动作自动触发。
- 调试入口是否需要在开发模式下展示内部 run 和 artifact 信息。

## 自检

- 已移除具体代码、数据库细节、函数、路由、测试代码和提交命令。
- 已保留产品契约、页面语义、保存边界和验收标准。
- 已明确只有一个基础方案时，六类页面各自只保留一个当前结果。
