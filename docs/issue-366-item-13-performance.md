本记录回应 [issue #366 第 13 项](https://github.com/jihegao/spare_mvp/issues/366)，不关闭整个 issue，也不将尚未完成的验收项标为完成。

## 实现与范围

生产实现已由提交 `0a3dd80264cd27b602a3a7e2a86b746d8311dc91` 进入 `main`，本记录所在 PR 补充交付证据和本地实验忽略规则，不重复引入该实现。

- `CompiledSimulation` 在分析 worker 中预编译结构，每个样本独立复制可变状态及随机数状态。
- 保留原保障作业执行顺序，按状态变化触发资源分配，通过活动作业索引减少扫描；没有展开所有随机分支，也没有将保障 DAG 擅自改成并行语义。
- 小时可用度、每日战备完好率及停机区间保持原口径；轮询型资源等待次数改为状态触发尝试次数。
- 蒙特卡洛页面增加“运行五项分析（各 50 样本）”，逐项调用已有分析接口、显示结果并独立计时。每项完整完成且启动至显示耗时 ≤60 秒才标记达标，五项累计时间不作为判定条件。

## 验收口径差异

issue 原文的验收基准是“当前默认数据库中的 F35 案例”。本轮用户随后明确要求在 **4700-4 的 J35 案例**实测，并澄清 **每项分别不超过 1 分钟，而非五项累计不超过 1 分钟**。

因此以下是 J35 的后端性能证据，不能替代 issue 中 F35 案例的完整验收，也不能把后端计时当作浏览器显示计时。原 issue 的五个复选框仍应保持未完成，直到确认采用的验收案例并补齐页面实测。

## 2026-09-18 J35 实测

- 部署版本：`0a3dd80264cd27b602a3a7e2a86b746d8311dc91`。
- 主机：4700-4，Windows，AMD Ryzen 7 4700U，8 核；Python 3.12.13。
- 案例：目标机案例版数据库中的“J35-43天使用可用度验证”，8 架飞机、423 个故障行为组件、104 个任务波次、61,920 分钟。
- 每项 50 个独立样本，8 个并行 worker，五项依次执行；各组使用不重叠的种子区间。
- 计时包括规范输入编译、样本执行、聚合、结果投影及 JSON 序列化，不包括 HTTP 传输和浏览器绘制。

| 功能 | 种子范围 | 完成样本 | 失败样本 | 后端耗时 |
| --- | --- | ---: | ---: | ---: |
| 蒙特卡洛实验 | 0–49 | 50 | 0 | 45.52 秒 |
| 备件短板分析 | 50–99 | 50 | 0 | 47.06 秒 |
| 飞机转场携行清单分析 | 100–149 | 50 | 0 | 47.37 秒 |
| 任务可靠度评估 | 150–199 | 50 | 0 | 48.22 秒 |
| 停机因素分析 | 200–249 | 50 | 0 | 48.66 秒 |

“完成样本”指仿真执行成功，不表示样本中的全部业务任务成功。五项分别重新执行 50 次仿真，不将同一组轨迹重复计为 250 次执行。

详细结果保留在 4700-4 案例版目录下的 `data/outputs/j35-compiled-acceptance/`：`summary.json`、五项结果 JSON 和 `results.html`。私有数据库、原始案例及详细仿真结果不纳入版本控制。
