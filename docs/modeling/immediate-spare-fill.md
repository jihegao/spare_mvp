# 即时备件满足率

`aircraft_support_v1` 的 `spare_fill_rate` 表示首次实际备件分配请求中立即满足的需求数量 / 首次请求需求总数量。没有需求时为 `null`，页面显示 `--`。模型快照同时提供 `spare_demand_total` 和 `spare_immediately_filled_total`，每个产品通过 `spare_request` 事件保留需求数量和即时满足数量。

一次请求对应一个作业步骤，步骤中的多产品需求必须整体原子满足。需求 5 件、可用 3 件时即时满足数量为 0；多产品中任何一个不足时，整个步骤的即时满足数量均为 0。重试和后续调拨到货不会补记首次满足数量。同一作业的不同步骤分别计数。

统计时点沿用调度器原有资源顺序：普通节点在人员和设备检查通过后发起备件请求；组织保障模式先分配备件，再等待人员。即时成功必须发生真实库存预留或消费，单纯看到库存不计成功。组织模式已经预留但人员未到的请求可以计满足。取消时按原规则释放预留，不改写首次请求历史；之后的其他实际请求独立计数。新调拨的库存即使之后到货，也不回补原请求。

按产品 `shortage_count` 表示首次未满足请求次数，`shortage_quantity` 表示其需求数量。短板排序采用短缺数量；观测请求短缺率为首次短缺请求次数 / 首次请求总次数，无请求时为 0；短板投影沿用 `shortage_probability` 字段承载该请求级概率。携行推荐的预计短缺数量与观测短缺次数、数量单独输出。

备件利用率按实际消耗数量除以实际携行数量计算，不再与即时满足率互补；零携行时为 `null`。跨样本的两个实际比率均使用分子分母总量之比作为汇总值，样本方差仍以各个有效样本比率计算；零分母和缺少原始数量的样本不进入有效样本数。

携行清单的推荐算法保持不变。页面和 XLSX 中“预计短缺数量”“规划满足率”属于推荐评估；“实际需求数量”“实际即时满足数量”“实际即时满足率”和“实际使用数量”来自仿真观测。满足下限按实际即时满足率判断。API 的 `projected*` 字段只表示规划，`satisfactionRate`/`observedFillRate` 表示由实际数量计算的同一口径，不得相互兜底。

已退役的 `aviation_support` 输出若没有权威满足率或首次请求计数，满足率为 `null`，页面明确显示不可用。库存余额不能用于推算该指标。可视化帧及异常快照同样保留不可用状态。

回归场景位于 `tests/test_spare_immediate_fill.py`，包括部分库存、多产品原子性、补给与重试、取消释放、共享库存竞争、分步骤去重、零需求、样本统计矩和旧模型兼容。
