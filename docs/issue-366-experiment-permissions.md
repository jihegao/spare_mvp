# 实验方案创建者与取消冻结

HTTP 创建方案将认证用户 ID 写入方案顶层 `created_by`，忽略客户端配置中同名字段。方案 ID 的确定性输入包含创建者，避免同一配置被另一创建者覆盖。更新保留持久化创建者；历史无主记录保持无主。

普通用户只能删除自己创建的方案；系统管理员和数据管理员保持原有删除权限。界面使用认证用户 ID 隐藏不可删除的操作，服务端再次校验。方案与路由项目必须匹配。

新增 `POST /projects/{project_id}/experiment-plans/{experiment_plan_id}/unfreeze`：全部已认证、有效角色可将 frozen 恢复为 draft；草稿重复调用不改变数据。操作清除冻结指纹和时间，通过原始 payload 比较交换检测并发修改，冲突返回 409。已有运行记录及其输入不删除。取消冻结入口取方案状态，不受最近一次运行状态覆盖。

沿用已有项目访问语义；此变更不引入新的项目 ACL 模型，也不自动认领历史记录。内部无 actor 的创建调用仍用于既有 fixture/系统流程，HTTP 创建始终要求认证。
