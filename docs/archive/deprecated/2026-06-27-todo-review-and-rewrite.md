## 主要评审问题

### 阻断项

1. `装备RMS指标分配` 中 MTBCF、任务可靠度、任务时长、关键故障占比、故障类型映射、MTBF 的换算关系尚未给出公式和字段口径。该问题不影响当前 `aircraft_support_v1` 建模、compile 和 `/api/runs` 主流程；阶段 0 只需记录为阶段 4 的 `decision-needed`，未明确前不能直接进入 RMS 算法实现。
2. 多处写有“完成集成”，但未说明集成对象、正式数据来源、API/artifact、失败状态和回滚口径。实现前必须拆成可验收的前后端闭环。
3. `具体需求待甲方确定` 的内容不能与确定性需求混在同一交付批次中，只能保留占位和最小 UI 调整。

### 重要项

1. 同一需求多次要求“备件规划评估模块与任务可靠度评估模块一致”，实现时必须抽为共享页面逻辑或共享契约测试，避免只改一个模块。
2. 多处要求“去掉编辑按钮”或“去掉即改即存，改为编辑按钮”，方向不完全一致。应按页面重新定义：哪些页面保留行内编辑，哪些页面改为弹窗/面板编辑。
3. 结果分析页面删除后，结果返回到 `蒙特卡洛实验` 页面，需要同步处理导航、旧路由别名、正式 projection artifact 显示位置和测试断言。
4. 保障活动工作项目需要引用 `基本保障活动`，并支持可搜索选择、自动回填和紧前作业编辑。该需求跨页面数据依赖较强，应先补数据模型和选择器契约。

### 建议项

1. `项目数据管理`、`建模颗粒度管理`、`建模表单管理` 之间存在配置来源关系，建议统一建模为“表单/字段/单位/字典”配置体系。
2. `海航大对应模块原型` 应补充截图或路径，否则只能先按文字需求实现通用编辑面板。
3. 删除页面或字段时，应在文档中说明数据迁移和旧数据展示策略。
